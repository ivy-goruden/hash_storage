# Hash Storage

Консольное key-value хранилище на C++17. Проект демонстрирует работу с шаблонными структурами данных, общий интерфейс хранилища, обработку ошибок и управление временем жизни записей.

При запуске можно выбрать одну из двух реализаций:

- `Hash_Map<T>`: хеш-таблица с цепочками коллизий и расширением при заполнении.
- `RedBlackTree<T>`: красно-чёрное дерево с балансировкой и управлением узлами через `std::unique_ptr`.

Обе реализации работают через общий интерфейс `Storage<T>`. Сейчас консольный интерфейс хранит записи типа `User`: фамилию, имя, год рождения, город и количество монет. Данные находятся в памяти процесса; для сохранения их можно экспортировать в файл.

## Возможности

- Добавление, получение, обновление и удаление записи по ключу.
- Проверка существования ключа, просмотр ключей и всех записей.
- Поиск записей по любому сочетанию полей.
- Переименование ключа с сохранением TTL.
- Время жизни записи в секундах и очистка просроченных записей перед обработкой команд.
- Загрузка записей из текстового файла и экспорт текущего хранилища.
- Ошибки ввода и операций возвращаются через `absl::Status` / `absl::StatusOr`.

## Сборка и запуск

Требуются CMake, компилятор с поддержкой C++17 и Abseil. В Debian/Ubuntu зависимости можно установить так:

```sh
sudo apt update
sudo apt install build-essential cmake libabsl-dev
```

Из корневой директории проекта:

```sh
cmake -S . -B build
cmake --build build --target main
./build/main
```

При старте выберите backend: `1` для `Hash_Map` или `2` для `RBTree`. Затем вводите по одной команде в строке. Для завершения введите `quit`.

Также из директории `src` можно запустить `make`: Makefile конфигурирует и собирает приложение, затем запускает его.

## Команды

Поля пользователя во всех командах идут в таком порядке: `фамилия имя год город монеты`. Аргументы разделяются пробелами; значения с пробелами в них не поддерживаются. В фильтрах и частичном обновлении `-` означает «любое значение» или «оставить без изменений».

| Команда | Формат | Назначение |
| --- | --- | --- |
| `SET` | `SET <ключ> <фамилия> <имя> <год> <город> <монеты> [EX <секунды>]` | Добавить запись, при необходимости задать TTL. |
| `GET` | `GET <ключ>` | Получить запись. |
| `UPDATE` | `UPDATE <ключ> <фамилия\|-> <имя\|-> <год\|-> <город\|-> <монеты\|->` | Обновить указанные поля. |
| `DEL` | `DEL <ключ>` | Удалить запись. |
| `EXISTS` | `EXISTS <ключ>` | Проверить наличие ключа. |
| `KEYS` | `KEYS` | Показать ключи. |
| `RENAME` | `RENAME <старый_ключ> <новый_ключ>` | Переименовать ключ. |
| `TTL` | `TTL <ключ>` | Показать оставшееся время жизни в секундах. |
| `FIND` | `FIND <фамилия\|-> <имя\|-> <год\|-> <город\|-> <монеты\|->` | Найти записи по полям. |
| `SHOWALL` | `SHOWALL` | Показать все записи. |
| `UPLOAD` | `UPLOAD <путь_к_файлу>` | Загрузить записи из текстового файла. |
| `EXPORT` | `EXPORT <путь_к_файлу>` | Сохранить записи в текстовый файл. |

`TTL` доступен только для записей, созданных с параметром `EX`. Просроченные записи удаляются при обработке следующей команды.

## Пример

```text
Select storage system:
1. Hash_Map
2. RBTree
> 2
SET user:1 Ivanov Ivan 1998 Moscow 120 EX 3600
OK!
GET user:1
Ivanov Ivan 1998 Moscow 120
UPDATE user:1 - - - - 150
OK!
FIND - - - Moscow -
1)user:1
TTL user:1
3599
EXPORT users.txt
Exported 1 records
quit
```

## Файл данных

`UPLOAD` читает по одной записи на строку в формате:

```text
<ключ> <фамилия> <имя> <год> <город> <монеты>
```

Пример:

```text
user:1 Ivanov Ivan 1998 Moscow 120
user:2 Petrova Anna 2001 Kazan 45
```

Некорректные строки при загрузке пропускаются. `EXPORT` записывает данные в этом же формате. Хранилище не загружает и не сохраняет файлы автоматически.

## Структура проекта

- `src/classes/storage.hpp` — базовый интерфейс, узел записи и общие операции.
- `src/classes/hash_map.hpp` — шаблонная хеш-таблица.
- `src/classes/red_black_tree.hpp`, `src/classes/red_black_tree.tpp` — шаблонное красно-чёрное дерево.
- `src/Interface/controller.cpp` — обработка команд и работа с хранилищем.
- `src/Interface/gui.hpp` — выбор backend’а и интерактивный ввод команд.
- `src/Interface/user.hpp` — модель пользователя и фильтрация по полям.

## Технологии

C++17, CMake, Abseil Status/StatusOr, шаблоны, `std::unique_ptr`, хеширование с цепочками и красно-чёрное дерево.
